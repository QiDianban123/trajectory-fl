## 一、页面建议标题

- 主标题：**概要设计——联邦实验：三种训练方式的公平对比**
- 副标题：集中式 Centralized / 本地独立 Local-only / 联邦 Federated（FedAvg）

## 二、上屏要点（PPT 内建议文字，5 条）

1. **目标（F6）**：同一数据划分、同一模型结构、同一初始权重、同一评价口径下，对比三种训练方式。
2. **三种模式定义**：集中式（汇总全部数据训练 1 个模型）；本地独立（5 个 RSU 各自只用自己的数据训练）；联邦（Server 下发全局模型 → Client 本地训练 → FedAvg 聚合）。
3. **公平性设置**：相同 `split_id` / 相同模型 / 相同 seed 初始状态 / 相同 Trainer / 相同 ADE·FDE 评价。
4. **FedAvg 按有效训练样本数加权**：$w_{r+1}=\sum_{i\in S_r}\frac{n_i}{\sum_j n_j}\,w_{r+1,i}$，非浮点 buffer 采用 `preserve_global`。
5. **计划**：D5 模型+Trainer → D7—D9 联邦轮次与 FedAvg → D10 调优 → D11—D13 三模式正式对比与图表。

## 三、讲稿（口播逐条稿）

### 开场（约 15 秒）

"我负责的是**联邦实验模块的概要设计**。我们的问题不是'联邦学习能不能预测轨迹'，而是——**在完全相同的条件下，把数据收上来集中训练、让每个路侧单元各练各的、还是做联邦协作，三种做法到底差多少**。所以这一页的核心词是'**公平对比**'。"

### 第 1 条 目标（约 15 秒）

"需求 F6 要求：同一套数据划分、同一个模型结构、同一份初始权重、同一个评价标准下，跑通集中式、本地独立和联邦三种模式。`docs/federated_design.md` 和 `docs/design.md` 已经把这套口径冻结了，后面所有实验都复用同一套 split、模型契约、初始状态、seed 和评价实现。"

### 第 2 条 三种模式定义（约 30 秒）

"三种模式分别是——

- **集中式（Centralized）**：把 5 个 RSU 的训练数据合并成一份，交给共享 Trainer 训练一个全局模型。它是数据理想汇聚的参照上界。
- **本地独立（Local-only）**：5 个客户端**不交换任何参数**，各自只用自己那份 Non-IID 数据、从同一基线初始状态出发各训各的。它回答的是'数据不出本地、但不协作'的下界。
- **联邦（Federated）**：Server 每轮把全局模型下发给选中的客户端，客户端用自己的本地数据训练几个 epoch 后只上传参数更新，Server 用 FedAvg 聚合出新一轮全局模型，循环 R 轮。它模拟的是'数据不出本地、但协作'。

三种模式都只通过**共享 Trainer**训练，禁止复制训练循环。"

### 第 3 条 公平性设置（约 30 秒）

"为了让对比结论可信，四件事必须完全一致：

1. **数据口径**：先按车辆/场景切分 train/val/test、再滑窗，训练集专属 scaler，杜绝泄漏；客户端按道路空间区域形成 5 个可解释的 Non-IID 划分（D4 实现）。
2. **模型**：同一 LSTM Encoder-Decoder 契约 `forward(history[B,75,2]) -> [B,125,2]`。
3. **初始权重**：用同一 seed 生成一份基线 `state_dict`，Local-only 每个客户端拿到的是**全新模型实例 + 基线状态的深拷贝**，客户端之间绝不共享训练后的参数。
4. **评价**：统一反归一化到米制物理坐标后计算 ADE/FDE，同一 `ResultRecord`/JSON/CSV schema（成员⑤ 负责）。

一句话：**除"数据是否合并、参数是否交换"外，其余全部相同**，差异只能来自训练方式本身。"

### 第 4 条 FedAvg 公式（约 20 秒）

"联邦聚合我们采用按**有效训练样本数**加权的 FedAvg：第 r 轮新全局权重是各客户端本地更新按其有效样本数 $n_i$ 占本轮总样本数比例的加权平均。注意权重是**实际参与训练的有效样本数**，不是 batch 数、不是客户端声称的容量。对整数、布尔这类非浮点 buffer，加权平均没有语义，我们固定采用 `preserve_global`——保留全局值，避免类型转换和取整歧义。数值实现在 D8 完成，并配人工数学用例做精确单测。"

### 第 5 条 计划与收敛分析（约 25 秒）

"落地节奏：D5 实现 LSTM 与 Trainer → D7—D9 实现联邦轮次循环与 FedAvg 数值 → D10 超参数调优 → D11—D13 跑正式三模式对比、出图、写汇总。

收敛分析计划：每个 epoch/每轮记录 train/validation loss 与 best epoch，checkpoint 带 schema_version/seed/split_id 元数据；每个 run 独立 `run_id` 输出到 `outputs/<run_id>/`，由 `metrics.json`、`metrics.csv`、`figures/`（收敛曲线、轨迹对比、模式对比图）支撑数值回溯。"

### 收尾（约 10 秒）

"以上就是联邦实验的概要设计——**一套公平口径、三种模式、一个加权公式**。谢谢，接下来请 成员⑤ 介绍评价体系。"

## 五、可能被提问的答辩 Q&A

| 提问 | 回答要点 |
|---|---|
| 为什么一定要三种模式对比？ | F6 验收标准要求三种模式同口径对比；集中式=数据理想汇聚参照，Local-only=无协作下界，联邦=协作方案，三者差距才能量化联邦的价值（非 IID 下 Local-only 每个客户端样本少、易过拟合）。 |
| Non-IID 怎么保证"可解释"？ | 按道路纵向空间区域把训练集映射到 5 个模拟 RSU，区域样本不足时合并相邻区域、不复制样本填充；每条客户端记录区域边界与车辆数。 |
| FedAvg 为什么按样本数而不是按客户端数加权？ | 客户端数据量不均（Non-IID），按有效样本数加权让数据多的客户端贡献更大，收敛与精度更稳；分母是实际有效样本数而非声明值。 |
| 联邦和 Local-only 都"数据不出本地"，区别在哪？ | Local-only 从不交换参数，每客户端模型只见本地数据；联邦通过 Server 聚合让各客户端共享全局知识，同时原始轨迹不上传。 |
| 公平性怎么防"作弊"？ | 相同 split_id/模型/seed 基线/评价实现；Local-only 客户端必须全新模型实例+基线深拷贝，禁止把任一客户端训练结果当另一客户端初始状态。 |
| 客户端失败怎么办？ | 联邦契约要求显式 `ClientFailure` 记录（失败阶段/类型/消息/可重试），失败更新不进 FedAvg，但必须进轮次日志与最终记录，不允许静默跳过。 |
