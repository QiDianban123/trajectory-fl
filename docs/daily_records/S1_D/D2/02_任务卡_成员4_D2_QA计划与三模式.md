## 二、子任务 1：代码质量保证计划（QA）— 完成 ✅

### 1. Code Review 流程（MR 必须审查后合入）

- **分支策略**：遵循 docs/git_workflow.md 的 main/dev/feature 分支模型；所有合入必须先提 MR。
- **硬性门槛**：**MR 未经至少 1 名非作者评审通过，禁止合入 main/dev**；P0 模块（federated、data 防泄漏、评价）建议 2 人评审。
- **评审清单（QA 检查项）**：
  - 接口一致性：不私自改动 D2 冻结契约（改动必须记录影响范围并同步 design/配置/实现/测试）；
  - 禁止复制训练循环（一律委托共享 Trainer）；
  - 防数据泄漏：切分先于滑窗、scaler 只拟合 train、验证/测试不得拟合；
  - 错误可定位：缺文件、错误配置、无效数值给出明确错误而非静默失败；
  - 非浮点 buffer 策略、Local-only 隔离（深拷贝基线 + 全新模型实例）；
  - 测试配套：新增核心函数必须有正常/边界/异常用例。
- **评审记录**：评审意见留痕在 CodeArts MR 评论/缺陷单中，作为过程证据（成员⑤ 归档截图）。

### 2. CodeArts CodeCheck 检查项（建议配置）

| 类别 | 检查项 |
|---|---|
| 规范 | PEP8/Ruff（`python -m ruff check src tests` 必须通过） |
| 正确性 | 未使用变量/未定义名称、潜在类型错误、除零与 NaN/Inf 传播路径 |
| 复杂度 | 圈复杂度/嵌套深度告警，超过阈值的函数要求拆分或注释说明 |
| 安全 | 路径逃逸拒绝（run 输出目录）、禁止提交原始数据/密钥、日志不记录设备路径与账户 |
| 复制 | 重复代码检测（重点：训练循环不得复制） |

- 触发方式：每次 MR 自动/手动触发 CodeCheck；结果作为合入门禁之一。
- 说明：CodeArts CodeCheck 为平台管理证据（对应毕业要求 12.2），本地以 Ruff+pytest 作为等价质量门禁每日执行。

### 3. 缺陷修复闭环规则

- **闭环路径**：提出（CodeArts 缺陷单，含复现/日志/截图）→ 指派负责人 → 修复 + 单测 → CodeCheck/Ruff 复检 → Reviewer 确认 → 回归（pytest）→ 关闭。
- **分级时限**：P1（阻塞/数据错误）当日闭环；P2（功能缺陷）迭代内闭环；P3（建议/优化）记录跟踪。
- **回归门禁**：每次功能变更至少执行
  ```powershell
  python -m pytest -q
  python -m ruff check src tests
  python -m src.cli validate-config
  ```
- **验证基线（D2 已有证据）**：`python -m pytest -q`（40 项通过）、Ruff、validate-config 均已通过（见 docs/D2.md、docs/daily_records/D2.md）。
