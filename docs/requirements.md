# 需求基线 V1.0

**状态：** D1 评审基线；**日期：** 2026-08-31；**变更规则：** D2 接口冻结前可由团队评审修改，之后以 Issue 记录影响。

## 目标、边界和术语

目标是在相同的数据划分、模型结构和评价口径下，比较集中式、本地独立和联邦训练的车辆未来轨迹预测结果。系统模拟 RSU 客户端，不实现真实网络通信、硬件控制、差分隐私或安全聚合。

| 术语 | 约定 |
|---|---|
| history/future | 单车历史/未来二维坐标序列，形状分别为 `[T_h,2]`、`[T_f,2]` |
| 客户端/RSU | 仅存储分配给自己的训练数据的模拟训练节点 |
| Non-IID | 由道路空间区域或场景造成的、可量化的数据分布差异 |
| ADE/FDE | 反归一化物理坐标中的平均/最终欧氏位移误差，单位米 |
| split_id | 按车辆或场景先切分 train/val/test 后生成的、可重建的数据划分标识 |

## P0 功能需求与可验收标准

| ID | 需求 | 验收标准 |
|---|---|---|
| F1 | 读取、清洗、归一化和切分一套主数据集 | 固定小样本能产生时间有序标准样本；统计缺失/异常；训练集统计量可逆且不使用验证/测试数据 |
| F2 | 可视化 | 一张图清楚区分 history、真实 future 与 prediction，含坐标、图例和输出路径 |
| F3 | 基础预测模型 | `forward(history[B,T_h,2]) -> [B,T_f,2]`；可训练、保存、加载，输出无 NaN/Inf |
| F4 | 多客户端划分 | 客户端训练集并集完整；按空间/场景形成可解释 Non-IID；无跨 split 泄漏 |
| F5 | 联邦模拟 | Client 本地训练，Server 下发/收集，FedAvg 按有效训练样本数加权；轮次记录可追踪 |
| F6 | 三种模式 | 同一 split、模型、初始权重和指标下运行 Centralized、Local-only、Federated，并保存统一结构产物 |
| F7 | 评价和汇总 | 自动输出 ADE/FDE、结果表、轨迹图、收敛图、模式对比图；数值可回溯原始运行 |

## 质量约束与 P1

- 数据必须先按车辆 ID 或场景划分，再做滑窗；禁止随机帧切分。
- 归一化统计仅基于训练集；指标一律在反归一化坐标中计算。
- 每个运行输出唯一 `run_id`；不得删除失败运行或在代码中手改正式配置。
- P1：YAML、命令行、固定随机种子、断点保存、自动汇总和常速度 sanity baseline。P2 项目均不进入本周期。
