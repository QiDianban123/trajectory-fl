# 开发人员参考清单

本目录保存项目总计划与开发阅读入口。开始工作前先确认当前阶段，再按角色读取对应工作包；需求与冻结接口优先级高于个人理解或临时口头约定。

## 1. 全员必读顺序

1. [开发计划书 V2.0](开发计划书.md)：D3—D10 四阶段、A—G 分工、阶段门禁与验收。
2. [工作包总索引](../../work_packages/README.md)：进入当前阶段目录并打开自己的 `A.md`—`G.md`。
3. [命名与证据规范](../../work_packages/naming_conventions.md)：工作包、分支、Commit、MR、测试和每日证据要求。
4. [需求基线](../docs/requirements.md)：F1—F7、M1—M6、AT-01—AT-08 的验收依据。
5. [D2 设计基线](../docs/design.md)：已冻结的数据、模型、训练、联邦、评价和结果 schema。
6. [测试计划](../docs/test_plan.md)：测试层级、质量门禁和验收用例。

## 4. 开始编码前检查

```powershell
python -m ruff check src tests
python -m pytest -q
python -m src.cli validate-config
git status
```

Git 规范正在从旧版 `main + feature` 过渡到 `main/dev/feature`。D3 开始前，A/F 应先将 D2 评审基线通过 MR 合入 `dev`，并同步更新仓库中的 [Git 工作流](../docs/git_workflow.md)。在同步完成前，以开发计划书与工作包命名规范的工作包、分支和 MR 规则为准。
