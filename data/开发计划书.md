## 6. 命名与配置管理规范

### 6.1 工作包、目录和文件

- 工作包编号：`S<阶段>-<角色>-<序号>`，例如 `S1-B-01`。
- 阶段说明目录：工作区根目录的 `work_packages/S<1-4>_D<起始>-D<结束>/<A-G>.md`；每个阶段目录集中放置 A—G 的工作文件。该目录用于任务分工，仓库中的 Commit、MR、评审和日报仍是过程证据来源。
- 阶段说明文件：`S1_D3-D4.md`、`S2_D5-D6.md`、`S3_D7-D8.md`、`S4_D9-D10.md`。
- Python 文件/函数/变量：`snake_case`；类：`PascalCase`；常量：`UPPER_SNAKE_CASE`。
- 测试文件：`tests/<层级>/test_<模块>.py`；测试函数：`test_<行为>_<预期>()`。
- 配置：`configs/experiments/<mode>_<scale>.yaml`，例如 `federated_smoke.yaml`。
- 输出：`outputs/<run_id>/`；`run_id` 必须唯一、可排序且不含个人路径。

### 6.2 Git 分支、提交和 MR

```text
main：受保护发布分支，只接收里程碑 MR
dev：受保护集成分支，始终保持测试通过
feature/fix/test/docs/chore：从 dev 创建，经 MR 合入 dev
```

分支示例：

```text
feature/s1-b-highd-adapter
feature/s2-g-centralized-runner
fix/s3-d-fedavg-weight
test/s4-f-clean-environment
docs/s4-e-result-analysis
```

Commit：`<type>(<scope>): <动词短句> [工作包][需求/验收]`

```text
feat(data): implement highd field mapping [S1-B-01][F1]
test(federated): verify weighted aggregation [S3-F-02][AT-05]
feat(experiments): add reproducible run matrix [S4-G-01][F6]
```

MR：`[工作包][需求/验收] 简短标题`，例如 `[S1-B-01][F1] Implement highD adapter`。

进入 D3 前，A/F 必须先创建或确认 `dev`，将 D2 评审分支经 MR 合入，并同步更新仓库 `docs/git_workflow.md` 为 7 人与 `main/dev/feature` 新基线，防止两套规范并存。

### 6.3 每日真实证据

- D3 起 A—G 每人每天至少一项有效 Commit、MR 更新或可审计评审；代码角色优先提交生产代码和测试。

- 日报记录工作包、Issue、分支、Commit SHA、测试结果、MR、评审者和阻塞。
- CodeArts/Git 看板、Commit、MR、CodeCheck 和评审记录为主证据，截图仅作补充。

## 7. 统一质量门禁与完成定义

每项工作包关闭前至少执行：

```powershell
python -m pytest -q
python -m ruff check src tests
python -m src.cli validate-config
```

Definition of Done：

- 实现符合冻结接口和工作包验收条件，无个人绝对路径、密钥或大型产物。
- 新增/修改逻辑附正常、边界和异常测试。
- Ruff、相关 pytest、配置校验及阶段冒烟通过，无未解释 NaN/Inf 或静默异常。
- 至少一名非作者评审；数据切分、指标、FedAvg、公共接口需两人确认。
- 配置、README/API 注释、每日记录和需求追踪同步更新。
- MR 合入 `dev` 后仍可复现；里程碑回归通过后才允许 `dev`→`main`。

## 8. 实验公平性

1. 先按 vehicle/scenario 划分 train/validation/test，再滑窗；scaler 只拟合 train。
2. ADE/FDE 必须在 inverse-transform 后的米制坐标计算。
3. 三模式复用同一 `split_id`、模型、初始化状态、seed、评价和结果 schema。
4. 明确记录 epoch/round/local epochs、样本访问量、参与客户端、耗时和资源。
5. 正式配置进入版本控制；运行产物保存配置副本、代码 SHA、数据 manifest 和失败原因。
6. 联邦结果无需优于集中式；必须如实解释 Non-IID、客户端漂移和预算差异。

## 9. 风险、降级和阻断规则

| 风险 | 预警信号 | 责任人 | 应对 |
|---|---|---|---|
| highD 不可用或字段不符 | D3 无合法可读样例 | B/A | 立即评审备选数据；不静默伪造字段 |
| 数据泄漏 | vehicle/scenario 跨 split | B/F | 停止训练，修复 split 与断言 |
| 模型不学习/NaN | 小样本 loss 不降 | C/F | 检查 scaler/shape/lr；常速度基线定位 |
| FedAvg 错误 | 人工状态聚合不精确 | D/F | 阻止进入多轮实验，修复样本权重/状态策略 |
| 实验不可复现 | run 缺配置/SHA/split/seed | G/F | 运行前门禁拒绝启动或标记失败 |
| 时间不足 | 阶段偏差超过 0.5 天 | A/全员 | 减少数据量/轮数/seed，不删除三模式完整链路 |
| Git 规范冲突 | `main` 与 `dev` 流程不一致 | A/F | D3 前更新 Git 手册和保护规则 |

降级顺序：取消全部 P2 → 减少超参数组合 → 采用 1 个主 seed + 2 个小规模复核 → 缩小样本与联邦轮数；不得删除 Centralized、Local-only、Federated 或 AT-01—AT-08 核心链路。
